# Glossary of Fused Terms

This glossary provides a cross-disciplinary dictionary, mapping the scriptural concepts explored in this book directly to their software engineering and artificial intelligence equivalents.

---

*   **Intelligence (Information & Truth):** The fundamental coordinate of reality, defined as the light of truth ([Doctrine and Covenants 93:36](../../gospel-library/eng/scriptures/dc-testament/dc/93.md)). In engineering, this represents the clean parameters, data structures, and optimized mathematical weights that conduct the logic of a system.
*   **Specification (Spiritual Creation):** The complete pre-physical blueprint of intent, requirements, and constraints ([Moses 3:5](../../gospel-library/eng/scriptures/pgp/moses/3.md)). In engineering, this is the declarative configuration file, design specification document, or prompt system instructions that must precede physical code execution.
*   **Verification (Feedback Loop):** The active inspection and observation of a creation until it aligns with the specification ([Abraham 4:18](../../gospel-library/eng/scriptures/pgp/abr/4.md)). In engineering, this maps to validation, unit testing, integration sweeps, and the human evaluation gate.
*   **Bilateral Covenant (Alignment Contract / SLA):** A binding agreement of mutual promises, reliable boundaries, and clear terms of trust ([Doctrine and Covenants 82:10](../../gospel-library/eng/scriptures/dc-testament/dc/82.md)). In engineering, this is the interface contract or Service-Level Agreement (SLA) that guarantees predictable inputs and outputs across system boundaries.
*   **Stewardship (Agent Bounds):** An appointed responsibility over a specific portion of a creation, accompanied by accountability ([Doctrine and Covenants 104](../../gospel-library/eng/scriptures/dc-testament/dc/104.md)). In engineering, this represents the scope limitation, tool access, and local state management of a subagent or microservice.
*   **Spirit-Matter (Physical Continuity):** The physical reality of all existence, differing only in degree of purity and visibility ([Doctrine and Covenants 131:7–8](../../gospel-library/eng/scriptures/dc-testament/dc/131.md)). In engineering, this is the physical silicon and hardware weights that execute and contain software instructions.
*   **Heart-Softening (Resource Release / Attention Yielding):** The act of putting down active resistance and surrendering self-will ([Alma 12:10](../../gospel-library/eng/scriptures/bofm/alma/12.md)). In engineering, this represents clearing execution buffers, invalidating stale cache connections, and releasing memory locks.
*   **Zion (Distributed Consensus / Microservices Orchestration):** A state of perfect relational alignment, unity, and shared purpose ([Moses 7:18](../../gospel-library/eng/scriptures/pgp/moses/7.md)). In engineering, this is a peer-to-peer distributed consensus network or synchronized microservices architecture aligned to a unified schema.
*   **Dross (Noise / Defect):** The foreign elements and noise that corrupt the purity of a substance. In engineering, this is the code bloat, data noise, or overfitted parameters that cause compilation errors or degraded model performance.
*   **The Veil (Context Boundary):** The separation between the steward's immediate perception and the ultimate source of light ([Ether 3:6](../../gospel-library/eng/scriptures/bofm/ether/3.md)). In engineering, this maps to the API gateway or abstraction layer that hides the complex execution logic of the model, which the steward accesses through proposal queries.
